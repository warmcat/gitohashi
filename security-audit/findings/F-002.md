# F-002 — dump_cb sul not cancelled at protocol destroy

## Location

- `src/protocol_gitohashi.c:328-338` (`dump_cb`, reschedules itself every 1s)
- Scheduled at `src/protocol_gitohashi.c:450` (PROTOCOL_INIT)
- Missing cancel in `LWS_CALLBACK_PROTOCOL_DESTROY` (:453-462)

## Build gating

Requires a vhost destroy with the lws context still servicing its event
loop.  The standalone daemon only destroys vhosts during context teardown
(no subsequent service iterations), and nothing in-tree destroys vhosts at
runtime today — reachable only via the `GOH_LWS_PLUGINS=ON` plugin
dimension loaded by a host that destroys/recreates vhosts at runtime, or a
future gitohashi-side runtime-vhost feature.  Hence Info: a real defect with
no current trigger path.

## Attack path

1. Host destroys the gitohashi vhost at runtime → lws delivers
   PROTOCOL_DESTROY → vhd (protocol per-vhost priv) is not itself freed, but
   the vhost and its priv are torn down as part of vhost destruction.
2. The still-scheduled 1s sul fires `dump_cb` up to a second later.
3. `lws_container_of(sul, struct vhd_gitohashi, sul)` over the freed priv →
   `lws_sul_schedule(vhd->context, ...)` writes through freed memory (UAF),
   and the reschedule would keep the loop firing.

## Evidence

```c
static void
dump_cb(lws_sorted_usec_list_t *sul)
{
	struct vhd_gitohashi *vhd = lws_container_of(sul, struct vhd_gitohashi, sul);
	//lws_threadpool_dump(vhd->tp);
	lws_sul_schedule(vhd->context, 0, &vhd->sul, dump_cb, 1 * LWS_US_PER_SEC);
}
```

PROTOCOL_DESTROY contains no `lws_sul_cancel(&vhd->sul)`.

## Impact

None today (no in-tree runtime vhost destruction).  Latent UAF for plugin
embedding hosts.

## Remediation sketch

`lws_sul_cancel(&vhd->sul);` at the top of PROTOCOL_DESTROY — or delete the
sul machinery entirely, since the stat dump it was meant to do is already
commented out.
