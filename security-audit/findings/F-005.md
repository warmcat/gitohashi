# F-005 — puri-failure early return orphans the req

## Location

- Early return: `src/protocol_avatar-proxy.c:108-112`
  (`puri = lws_parse_uri_create(vhd->remote_base); if (!puri) return 1;`)
- Caller has already unlinked the req from `owner_waiting`:
  `:174-184` (`create_waiting_client_requests` does
  `lws_dll2_remove(&r->next)` then calls in)
- Correct sibling cleanup for the connect-failure leg: `:151-159`
  (close/unlink/dll2-remove/free) — the puri leg bypasses all of it

## Build gating

Requires `remote_base` to fail `lws_parse_uri_create()` — an operator
misconfiguration (the pvo is never validated at PROTOCOL_INIT, :314).

## Attack path

1. Vhost starts with an unparseable `remote-base` (INIT succeeds — no
   validation; only per-request parsing reveals the breakage).
2. First `mention()` (worker thread) queues a req on `owner_waiting` and
   cancels service.
3. Service thread `EVENT_WAIT_CANCELLED` → `create_waiting_client_requests`
   removes the req from `owner_waiting`, calls
   `__create_waiting_client_request`:
   - temp file created and fd opened (:96),
   - `lws_parse_uri_create` fails → `return 1` **before** the
     `lws_dll2_add_head(&r->next, &vhd->owner)` at :132 and before any
     cleanup.
4. The req is on no list and owns an open fd + a created temp file; no
   client wsi was created, so DROP_PROTOCOL will never see it → leaked for
   the process lifetime.  Repeats for every subsequent mention.

## Evidence

```c
	puri = lws_parse_uri_create(vhd->remote_base);
	if (!puri) {
		lwsl_notice("%s: parse uri %s: failed\n", __func__, vhd->remote_base);
		return 1;              /* fd open, temp created, req on no list */
	}
```

## Impact

Hygiene-class leak (memory + fd + temp file per mention) that only a
broken config reaches; no attacker control beyond volume via mentions.
Low severity, high confidence (flow-verified).

## Remediation sketch

Validate `remote_base` parseability once at PROTOCOL_INIT and fail the
protocol loudly; and/or give the puri-failure leg the same
close/unlink/dll2-remove/free cleanup the connect-failure leg has.
