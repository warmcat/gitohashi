# F-008 — unescaped URL elements into HTML meta content attribute

## Location

`lib/job/job.c:832-838` (HTML_STATE_HTML_META):

```c
CTX_BUF_APPEND("<meta name=\"Description\" content=\""
               "generated-by:gitohashi git web interface, "
               "repository: %s, mode: %s, path: %s, rev: %s\">",
               reponame ? reponame : "-", mode ? mode : "-",
               jg2_ctx_get_path(ctx, JG2_PE_NAME, NULL, 0) ? ... : "-",
               vid ? vid : "-");
```

No `ellipsis_purify()` on any interpolation — contrast the neighboring
`meta_header` (:600-606) which purifies every repo-derived string.

## Build gating

Default build, HTML/sandwich mode (the default `/git` view).  Active
content is fenced by the shipped CSP (`script-src 'self'`, no
unsafe-inline) — injection is limited to passive markup (content
spoofing, injected links/UI) inside the gitohashi origin.

## Attack path

1. The repo element must name a real, served repo (ctx create opens it).
2. **mode** and **vid** are free-form: an unknown mode keeps its raw
   string through job dispatch (the `else` branch at :927-930 falls to
   EMIT_STATE_TREE without rewriting the mode; only blog_mode rewrites
   unknown modes), and vid is the third URL element raw.
3. The meta line is emitted in HTML_STATE_HTML_META — *before* any job
   runs, so job-level failures do not prevent it.
4. `GET /git/<real-repo>/<payload>/…` with payload containing
   `"><a href=…>` (or any attribute-breaking markup; raw `"` is legal in
   an lws URI) breaks out of the `content="…"` attribute into the page
   head.

## Evidence

The same line also contains a copy-paste bug — the "path" slot is filled
with the repo *name* again (`jg2_ctx_get_path(ctx, JG2_PE_NAME, …)` at
:836-838) instead of the path element — indicating the interpolation was
never reviewed against the escaping policy every other emission in the
file follows.

## Impact

CSP-gated HTML injection: no script execution (script-src 'self' blocks
injected inline scripts and event handlers; style-src likewise), but
attacker-controlled passive markup inside the authenticated-looking page.
Low per the F-021-class precedent; high confidence the interpolation is
unescaped.

## Remediation sketch

Route all four interpolations through `ellipsis_purify()` (or at minimum
an HTML-attribute escaper) like the meta_header fields, and fix the
doubled-NAME slot.
