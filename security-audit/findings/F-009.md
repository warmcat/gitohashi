# F-009 — template reload race → OOB read into served pages

## Location

- Unlocked reads + wrap arithmetic: `lib/job/job.c:813-820` (META),
  `:846-854` (HEADER), `:1075-1083` (TRAILER) — e.g.
  `m = ctx->vhost->meta - ctx->html_pos > left ? left : ctx->vhost->meta - ctx->html_pos;`
  with `size_t m`, then `memcpy(ctx->p, vh->html_content + ctx->html_pos, m)`
- Offset/pointer writers: `__jg2_vhost_reference_html`
  (`lib/main.c:88-131`) under the vhost lock, re-run from every ctx create
  — mtime-based hot reload of the template is a documented, by-design
  feature ("it checks for changes and reloads if changed automatically")

## Build gating

Default build, sandwich (HTML) mode with a `html-file` template.

## Attack path

1. A sandwich spans multiple `jg2_ctx_fill` calls; the worker's
   `ctx->html_pos` persists across them.
2. Operator replaces/shortens the template while requests are in flight:
   the next ctx create (service thread) reloads `vh->html_content` and
   recomputes `vh->meta` / `vh->dynamic` / `vh->html_len` for the **new**
   content.
3. A worker re-enters fill with `html_pos` beyond the new offsets (or
   beyond the new, shorter `html_len`) — reading them **without** the
   vhost lock.
4. `vh->html_len - html_pos` is negative → size_t wrap → huge → `> left`
   → `m = left` → `memcpy(dst, html_content + html_pos, left)` reads up
   to a full fill buffer past the lwsac template allocation.
5. The OOB bytes are appended to the page being served (heap info leak
   into responses), or the worker crashes.

## Evidence

All three HTML states share the unsigned-compare shape; the setters hold
`vhost->lock`, the worker readers do not; `html_pos` is `size_t`
(private.h:416) and the marker offsets are `size_t` on the vhost.

## Impact

Operator-timing-gated OOB read into client responses (adjacent heap
contents, up to one fill buffer ≈4 KiB per hit) or a crash.  Low; medium
confidence (arithmetic verified; the race window depends on reload timing
during live traffic and was not reproduced).

## Remediation sketch

Compute `m` with a signed comparison and bail/reset the sandwich when
`html_pos` exceeds the current offsets (or snapshot the content pointer +
offsets into the ctx under the lock at first fill, making each sandwich
immune to later reloads).

## Status history

- 2026-09-06 — filed open by SA-003 (job-core pass).
- 2026-09-13 — fixed (f09d2b0): each HTML state clamps html_pos to the current offset when the template was hot-reloaded shorter mid-sandwich, emitting nothing for the vanished segment instead of computing a wrapped huge length; the response stays memory-safe (may truncate early).
- 2026-09-13 — audit-verified by SA-005 (Track A fix-delta pass): per-state clamps close the unsigned wrap (html_pos <= offset before every length computation). Accepted residual: the theoretical torn window between clamp and length-read under a same-nanosecond reload remains (size_t reads are practically atomic); snapshotting offsets under the lock stays on the shelf.
