# F-011 — libarchive writer leaked on every aborted snapshot

## Location

- `lib/job/snapshot.c:316-340` — `job_snapshot_destroy` frees trees,
  blob, lwsac — **not `ctx->a`**
- Destroying entry `:350-354`; ctx teardown re-invokes the job via
  `lib/main.c:354-359` (`ctx->job(ctx)` with `ctx->destroying` set)
- The two other exits do free it: `error_out` (:586-587) and completion
  step 3 (:574-575)

## Build gating

`JG2_HAVE_ARCHIVE_H` (libarchive found — the common build).

## Attack path

1. Unauthenticated client requests
   `GET /git/<repo>/snapshot/<repo>-<ref>.tar.gz` on any repo with
   content.
2. Client disconnects mid-transfer (trivial: close the socket).
3. wsi closes → threadpool task stopped → ctx destroy →
   `job_snapshot(destroying=1)` → `job_snapshot_destroy` — the libarchive
   writer (including gzip/bzip2/xz filter state) is never freed.
4. Repeat N times → hundreds of KB per attempt accumulate → daemon memory
   exhaustion (shipped systemd unit: LimitAS=1500M → OOM kill;
   Restart=on-failure recovers — degradation/DoS, not persistence).

## Evidence

`ctx->a` is non-NULL from `job_snapshot_start` success until one of the
two freeing exits; the destroy path added the lwsac/tree cleanup but
missed the archive handle.

## Impact

Unauth, unbounded-rate memory leak — practical memory-exhaustion DoS on
the default deployment.  Medium, medium-high confidence (leak path
code-verified; not runtime-reproduced in this pass).

## Remediation sketch

In `job_snapshot_destroy`: `if (ctx->a) { archive_write_free(ctx->a);
ctx->a = NULL; }` — and make `error_out` NULL it after freeing (completion
already does).
