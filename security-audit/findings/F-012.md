# F-012 — free(NULL) leak in remove_ongoing

## Location

`lib/job/search.c:47-59`:

```c
if (*pon == ctx->ongoing) {
        *pon = ctx->ongoing->next;      /* unlink from indexing_list */
        lwsl_err("---------- ongoing free %p\n", ctx->ongoing);
        ctx->ongoing = NULL;            /* pointer nulled first…  */
        free(ctx->ongoing);             /* …so this frees nothing */
        break;
}
```

## Build gating

None — default build; runs at every trie index completion (:825) and on
search-ctx destroy.

## Attack path

Unauth-triggerable search requests cause trie builds; each build's
completion unlinks the `ongoing_index` correctly but leaks the ~48-byte
struct.  Pusher-driven refs churn (each push → new refs hash → new trie
build) multiplies the leak.  Unbounded in principle, slow in practice.

## Evidence

The three-line sequence — `free` was clearly meant to run on the
unlinked node (cf. the log line printed with the pre-NULL pointer).

## Impact

Slow memory leak.  Low severity, high confidence.

## Remediation sketch

Keep a local `struct ongoing_index *o = ctx->ongoing;`, unlink, NULL the
ctx field, `free(o)`.
