# F-013 — freed root-tree pointer restashed and reused for the index walk

## Location

- `lib/job/search.c:413-422` — extent-walk level exhaustion runs
  `git_tree_free(lev->tree)` on every level **including the root**
  (`ctx->stack[0].tree == u.tree`)
- `:526` — second-walk setup does `ctx->stack[ctx->sp].tree = u.tree;`
  (the pointer just freed)
- `:690` — first deref (`git_tree_entry_byindex(lev->tree, …)`)

## Build gating

None — this is the normal trie-build path, unauth-triggerable via search
requests.

## Attack path

1. `git_commit_tree(&u.tree, …)` returns an owned reference.
2. The extent walk frees it at root exhaustion; the code only keeps
   working because libgit2's default-on object cache holds a second
   reference (gitohashi never disables caching).
3. In the straight-line window before the index walk re-uses the pointer,
   concurrent libgit2 activity on the other workers / cache-trim thread
   (reflist updates) can evict the tree from the cache — with refcount
   now 0 the object is actually freed → `git_tree_entry_byindex` on
   freed memory → UAF in the worker.

## Evidence

The root-exhaustion free at :413-421 is unconditional (the same code
tears down subtrees, which *are* re-looked-up in the second walk — only
the root is reused-dangling); snapshot.c's single-walk shape does not
have the pattern.

## Impact

libgit2 refcount-contract violation with a rare eviction race on top —
crash-class, not shown exploitable.  Low, medium confidence (violation
code-verified; eviction race reasoned, not reproduced).

## Remediation sketch

Re-lookup the root tree by oid for the index walk (as the walk already
does for every subtree), or skip the root free at extent-walk exhaustion
and let the index walk's own teardown own it.

## Status history

- 2026-09-06 — filed open by SA-004 (job-search pass).
- 2026-09-13 — fixed (ffd2b70): extent-walk exhaustion no longer frees the root tree at stack[0] (the index walk re-stashes it and job_search_destroy frees it via the stack, exactly one owned reference); the index walk's subtree exhaustion now frees its git_tree_lookup refs instead of leaking them.
- 2026-09-13 — audit-verified by SA-005 (Track A fix-delta pass): extent walk skips the root free (sp guard) keeping the owned reference for the index walk, which frees every level including root; refcount contract restored — the libgit2-cache grace is no longer load-bearing.
