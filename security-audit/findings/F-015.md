# F-015 — crafted `..` tree entries become tar-slip members

## Location

`lib/job/snapshot.c:498-499` (dir entries) and `:539-542` (blob entries):
`path` = walk prefix + `git_tree_entry_name(te)` →
`archive_entry_set_pathname(ae, path)` — no sanitization.

## Build gating

`JG2_HAVE_ARCHIVE_H` (common build).  Trigger requires a crafted-object
push: git clients refuse to *create* `..` path components, but a pusher
using plumbing can write raw tree objects with entry names `..`, and
gitolite repos accept them absent `receive.fsckObjects`.

## Attack path

1. Pusher crafts nested tree objects whose directory entries are named
   `..` (each nesting level is a separate tree object).
2. Walk prefix accumulates `<repo>-<ref>/../../…` — git forbids `/` in
   entry names, so traversal depth comes only from these crafted entries;
   nested crafted trees construct multi-level escapes.
3. Snapshot request serves a tarball/zip containing members like
   `<prefix>/../../evil` — path traversal **on extraction**.
4. Impact depends on the extracting tool: GNU tar / bsdtar refuse or
   strip `..` members; Python `tarfile` and older tools extract literally
   → files written outside the target directory.

## Evidence

No name validation in the walk; symlink/submodule entries already bail
out (safe-by-refusal), showing exotic entries are expected to be handled
at this layer.

## Impact

Downstream extraction hazard rooted in gitohashi serving unvalidated tree
names; Low, medium confidence (serving-side path code-verified; final
impact extractor-dependent).

## Remediation sketch

Reject or skip tree entries named `.` or `..` during the walk — cheap,
and closes the crafted-object route entirely.
