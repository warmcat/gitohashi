# F-016 — unbounded diff materialization (and friends) from repo content

## Location

- Primary: `lib/job/commit.c:183-201` — `git_diff_tree_to_tree` +
  `git_diff_print` stage the **whole patch** into `ctx->lwsac_head`
  (4-byte length-prefixed records, one per diff line) inside the single
  unyielded `job_commit_start` slice, before any output is streamed
- Same shape, smaller scale: `lib/job/tree.c:70` (one lwsac
  `tree_entry_info`+name per entry of the listed dir level),
  `lib/job/blame.c:226` (per-distinct-commit hunk-info + serialized
  signature strings)

## Build gating

Default build.  Repo-content-gated (pusher crafts the bomb), then
detonated by any unauthenticated `GET /git/<repo>/commit/<oid>` or
`/patch/<oid>` (or the pusher's own browser).

## Attack path

1. Pusher commits a change whose textual diff is huge — e.g. adds a
   ~500MB text file (binary files collapse to a one-line "Binary files
   differ", so text is required; trivially arranged).
2. Any client requests the commit or patch view → `job_commit_start`
   runs the full `git_diff_print` → `common_print_cb` appends every diff
   line into the per-ctx lwsac → ~diff-size heap usage, plus the worker
   is pinned for the whole generation (STOPPING unobservable inside the
   libgit2 call — F-010 family).
3. Two or three concurrent such views push the process against its
   LimitAS=1500M (shipped systemd unit) → process-wide allocation
   failures (lwsac_use returns NULL → diff print fails, the view errors
   out) or an OOM kill; Restart=on-failure recovers, so the result is
   degradation/DoS, not persistence.
4. Crafted multi-million-entry dirs (tree) and pathological blame
   histories accumulate the same way at smaller per-request scale.

## Evidence

No size cap on lwsac growth in any of these paths; the streaming loops in
`job_commit` only start after `job_commit_start` has staged everything;
libgit2 emits text diffs line-by-line with no bound.  Contrast `plain`
mode, which streams directly from libgit2's mmap of the object file and
is memory-cheap by design.

## Impact

Practical memory-pressure DoS on the default deployment, gated on repo
content (pusher) with unauthenticated detonation.  Medium, medium
confidence — mechanism code-verified; the AS cap plus graceful
lwsac-NULL failure bound the worst case at daemon-wide allocation stress
rather than silent corruption.

## Remediation sketch

Cap the accumulated diff (stop staging past e.g. 10MB and emit a
truncation marker — or restructure to stream the diff from the libgit2
callback directly into the output buffer via the existing partway
machinery instead of staging it), and bound tree-listing lwsac by entry
count.  Either also removes the single-slice worker pinning during bomb
generation.
