# F-017 — undersized per-item reserve → truncated, cached JSON

## Location

- Guard: `lib/job/blog.c:236` — `JG2_HAS_SPACE(ctx, 2500)`
- Emission: `:378-384` — pure_path[512] + pure_title[512] +
  pure_summary[2048] + pure_image[512] + ~80 format overhead ≈ **3644 max**

## Build gating

Blog mode (vhost flag + blog-repo-name, or `+`-prefixed repo
description); default build.

## Attack path

1. Repo pusher posts articles whose scraped first-paragraph summary
   purifies near the 2048 scratch cap (a long first paragraph — ordinary
   content reaches it).
2. The per-item loop breaks only when fewer than 2700 bytes remain; an
   item starting with [2700, 3644) bytes free passes the check.
3. The appends hit the `CTX_BUF_APPEND` clamp mid-string — the item's
   JSON is truncated without its closing quote/brace.
4. The whole page's JSON becomes unparseable for jg2.js, **and the
   malformed bytes are written to the JSON cache** — every subsequent
   viewer of the blog index gets the broken page until the repo's refs
   change (cache invalidation is ref-hash based).

## Evidence

`JG2_HAS_SPACE(ctx, 2500)` against the four scratch buffers' summed
maximum; the clamp (lws_snprintf) makes this truncation, not overflow —
malformed output, not memory unsafety.

## Impact

Persistent page breakage for the blog view (pusher-triggered, served to
all unauthenticated viewers until a ref change).  Low, medium confidence
(arithmetic verified; the leftover-window trigger is routine under
normal pagination).

## Remediation sketch

Size the guard to the item: break/resume when
`strlen(pure_path)+strlen(pure_title)+strlen(pure_summary)+
strlen(pure_image)+~100` exceeds the space left (the pattern log.c and
tree.c use), or raise the fixed reserve to ≥ 3700.

## Status history

- 2026-09-13 — filed open by SA-007 (job-blog pass).

- 2026-09-18 — **fixed** in `f352288`: the item space check moved after purification and sized to the actual field lengths (+160 overhead) so an oversized item is held for the next fill; both fill paths give a big enough window at its start (4096 wire / 8192 SSR capture slice) for a worst-case ~3.7k item.  An initial sign-compare -Werror was fixed and the commit amended before anything else built on it.
