# F-019 — duplicate-param strdup leak in jg2_repopath_split

## Location

`lib/util.c:141-180` — the urlarg loop of `jg2_repopath_split()`:

```c
if (klen == 1 && key_start[0] == 'h') {
        pp = strdup(p + 1);
        sr->e[JG2_PE_BRANCH] = (const char *)pp;   /* prior value leaked */
        ...
```

(same shape for `id` → `JG2_PE_ID` and `q` → `JG2_PE_SEARCH`)

## Build gating

None — default build, any request.

## Attack path

1. Unauthenticated client sends `GET /git/repo/log/x?q=aaa&q=bbb`
   (or a repeated `h=`/`id=`).
2. Param iteration 0 strdups `aaa` into `sr->e[JG2_PE_SEARCH]`;
   iteration 1 strdups `bbb` and overwrites the pointer — the `aaa`
   allocation is orphaned (`jg2_repopath_destroy` frees only the final
   pointer).
3. Repeat at request rate; each request leaks `strlen(value)+1` bytes
   (URL-bounded, ~≤1KB) — slow unauth memory growth, the same leak
   class as F-011/F-012.

## Evidence

Every other `sr` field is written exactly once; the param loop assigns
the three strdup'd fields unconditionally per matching key, with up to 4
params parsed per request.

## Impact

Slow unauthenticated memory leak.  Low, high confidence.

## Remediation sketch

`free((char *)sr->e[...]);` before reassignment — or ignore duplicate
keys after the first.

## Status history

- 2026-09-13 — filed open by SA-008 (lib-util pass).

- 2026-09-18 — **fixed** in `9d1829b`: free() of the prior strdup before reassignment for h=/id=/q= (free(NULL) no-op on first use).
