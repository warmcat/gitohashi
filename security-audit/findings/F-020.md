# F-020 — rei lwsac freed under rd->lock, read under vh->lock / unlocked

## Location

- Freer (repodir lock held by callers): `lib/conf/gitolite/common.c:196-202`
  — on a gitolite-admin HEAD change, `lwsac_free(&rd->rei_lwsac_head)`
  + `rei_head = NULL` + rescan
- Readers under the **vhost** lock (wrong lock): `lib/job/job.c:237-267`
  (cache-hash item 8 — walks `repodir->rei_head` and the rei conf
  strings inside `jg2_ctx_set_job`'s vh-lock region, :360-388) and
  `lib/job/job.c:141-151` (`__jg2_job_hash_visible_repos`, whose comment
  claims "requires vhost lock" suffices)
- Unlocked reader: `lib/job/repos.c:32` (`job_repos_start` picks up
  `ctx->rei` from `rei_head` with no lock)

## Build gating

None — default build; trigger is a gitolite-admin push (admin action)
coinciding with in-flight requests.  The 1s admin-head check throttle
bounds check frequency, not the race window.

## Attack path

1. Worker computes a repo-affiliated cache key under `vh->lock` — item 8
   walks the rei list reading names + gitweb config strings.
2. Concurrently, a request on the service thread runs
   `__jg2_conf_gitolite_admin_head` under `rd->lock`, sees the admin HEAD
   changed, and frees the whole rei lwsac before rescanning.
3. The worker's `lp_to_rei` chain walk and `jg2_rei_string` reads hit
   freed lwsac memory — garbage repo info hashed into cache keys (a
   stale or corrupted key can serve one view under another's URL until
   refs change) or a worker crash.  `job_repos_start`'s unlocked pickup
   can capture a dangling `ctx->rei` for the whole listing.

## Evidence

Three locking disciplines govern the same list: `rd->lock` on the
acl/meta paths (correct — same lock as the freer), `vh->lock` on the
job.c hash walks (the comment documents the wrong belief), none at the
repos-start pickup.

## Impact

Admin-timing race, read-side UAF — same class and grading as F-009
(operator-triggered timing, OOB/UAF read into outputs).  Low, medium
confidence (lock asymmetry code-verified; race not reproduced).

## Remediation sketch

Take `rd->lock` for the rei walks in job.c (cheap, uncontended —
meta_header already does exactly this), or refcount the rei lwsac per
ctx, or snapshot the needed name/conf strings into the ctx at create
time.
