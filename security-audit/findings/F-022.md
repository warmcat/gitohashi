# F-022 — stale vendored JS with known post-version security fixes

## Location

- `assets/showdown.min.js` — banner `/*! showdown v 2.0.0-alpha1 - 19-04-2018 */`
- `assets/highlight.pack.js` — banner `/*! highlight.js v9.18.1 */`

Both are served same-origin to every repo-content rendering path
(markdown → showdown, code files → hljs).

## Build gating

None — default assets.  Mitigations in depth: the strict CSP
(`script-src 'self'`) fences showdown's known post-2.0.0 XSS hardening
gaps (link schemes / attribute vectors), and the gitohashi preprocessing
neutralizes the raw-HTML routes; hljs operates on `san`'d text but
grammar ReDoS is not an XSS class and CSP does not apply to it.

## Attack path

1. Repo pusher commits a code file shaped to a known post-9.18.1 hljs
   grammar ReDoS vector (ReDoS-class fixes shipped in later 9.18.x /
   10.x upstream lines).
2. Viewer opens the file view → `hljs.highlightBlock` on the content →
   catastrophic backtracking → the viewer's tab hangs (client-side DoS
   per viewer, repeatable per crafted file).
3. The showdown leg has no live path today (CSP + preprocessing), but
   every future CSP loosening silently re-arms years of known markdown
   XSS fixes that this alpha predates.

## Evidence

Version banners in the vendored files; both upstream projects shipped
security releases after these versions (showdown's later 2.x line,
highlight.js's 9.18.5+/10.x).

## Impact

Hygiene/staleness with one plausible live consequence (viewer-tab hang
from crafted code files) and a defense-in-depth dependence on the
strict CSP.  Low, medium confidence (version-glance scope; no PoC run).

## Remediation sketch

Bump highlight.js to the current 10/11 line and showdown to the latest
stable 2.x; re-run the `./xss` corpus pages (no alert boxes) plus a
craftedy-code sanity check as the regression fence.
