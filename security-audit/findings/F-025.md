# F-025 — case-sensitive scheme gate in md_url

## Location

`lib/job/markdown.c:119-129` — `strncmp`-based checks against the
lowercase literals `"http://"`, `"https://"`, `"mailto:"`,
`"javascript:"`, `"data:"`, `"vbscript:"`.

## Build gating

None — default README/blog rendering.  The strict CSP
(`script-src 'self'`) blocks javascript:/data: execution, fencing the
live impact to markup/link injection.

## Attack path

1. Repo pusher writes `[click](JaVaScRiPt:alert(1))` (mixed case) into a
   README/blog.
2. `md_url`'s case-sensitive checks miss the scheme; it also fails the
   resolver prefixes, and the belt-and-braces percent-encoder passes it
   through raw (letters and `:` are url-safe).
3. The URL lands in `href="..."` as-is; browsers resolve scheme names
   case-insensitively, so this is a live `javascript:` link if the CSP
   ever stops fencing it (any script-src loosening re-arms it).

## Evidence

All scheme comparisons in md_url are `strncmp` with lowercase
literals; browsers treat schemes case-insensitively.

## Impact

CSP-fenced injection (click-phishing/markup only today) — but it
contradicts markdown.c's stated contract that raw XSS is removed
"entirely", making it a defense-in-depth failure worth closing.  Low,
medium confidence (read-verified; no browser PoC this pass).

## Remediation sketch

Case-insensitive scheme comparison (strncasecmp), or invert to an
allowlist: only http(s)/mailto/#// plus resolver-relative pass,
everything else becomes `#`.

## Status history

- 2026-09-18 — filed open by SA-016 (job-ssr pass).

- 2026-09-18 — **fixed** by retiring lib/job/markdown.c for the lws-md
  stock html sink, which matches schemes case-insensitively against an
  allowlist (http, https, mailto, fragments, root- and resolver-produced
  paths) and replaces everything else — javascript:, data:, vbscript: in
  any capitalization — with '#'; covered by test-md hostile-url goldens.
