# F-026 — fixed line arrays drop overflow lines from the rendered output

## Location

- `lib/job/markdown.c:879` — `struct md_line lines[2048]` with
  `if (count < LWS_ARRAY_SIZE(lines))` silently not appending beyond 2048
  lines
- `lib/job/markdown.c:620` — `struct md_line inner[128]` per blockquote
  level, same silent drop at 128 collected lines

## Build gating

None — default build.

## Attack path

1. A markdown document with more than 2048 lines (or a blockquote
  collecting more than 128 lines) has the excess lines silently omitted
  from the rendered HTML.
2. This is a content-integrity failure rather than a safety failure, but
  it is attacker-controllable: a hostile README can force the interesting
  parts (eg, security claims, license text) past the cap so the rendered
  page shows different content than the source a reviewer reading the
  file view sees.

## Evidence

Code-verified: both collection loops guard with `if (count < SIZE)` and
drop otherwise; no error, no marker in the output.

## Impact

Silent, attacker-shaped content divergence between the markdown source
and the rendered page.  Low severity (integrity, not memory safety).

## Remediation sketch

The retired renderer is replaced by the lws streaming markdown renderer,
which stages one line at a time and holds at most one line for the table
lookahead; there are no fixed line-count buffers, so nothing can be
dropped.  Past the single-line staging cap the line is reclassified as
escaped paragraph text, still emitting every byte.

## Status history

- 2026-09-18 — filed by SA-016 continuation; fixed the same day by the
  commit retiring lib/job/markdown.c in favor of the lws-md api.
